# MCRF optional Android engines · 0.1.0-dev.4

Each engine has its own APK and package ID: `org.mcrf.engines.csqtt`, `.qwdtt`, `.wdtt`, `.openflux`, `.olcrtc`, `.dnstt`, and `.warpscout`. Interface 1, OpenFlux bridge 2, SWG bridge 1. The main app checks the exact engine identity and matching APK signer before executing Android-installed libraries. Downloaded APK/cache files are never executed. The old `org.mcrf.engines` bundle is read only for migration; new imports request individual packages.

OLC RTC, DNSTT, OpenFlux, QWDTT, CSQTT, WDTT Plus and the WARP scanner are optional packages, not main-app native libraries/assets. CSQTT includes its own QWDTT wire bridge plus CSQTT transport; installing/removing the independent QWDTT package does not remove CSQTT's bridge. Private-config adapters preserve passwords, stable app installation binding and the complete call pool. No secret is passed in process arguments. Earlier shared-package WDTT/QWDTT/CSQTT HTTP checks passed on the connected phone; independent-package, VPN, reconnect, captcha and deployment checks are separate gates.

`ports/android/transports/build.ps1` builds pinned transports; `ports/android/build.ps1 -Task :engines:assembleRelease -TestRelease` explicitly produces development-signed APKs. Production signing must use a separate persistent key matching the main app.

Release assets use `mcrf-engine-<kind>-<abi>-release.apk`, where kind is one of the seven packages and ABI is arm64-v8a / armeabi-v7a / x86_64 / universal. `package-engines.ps1` verifies each package's identity, signer, ZIP16K alignment and exact executable allowlist, then writes individual byte counts and SHA256 sums. `package.ps1` rejects all optional executables in the main APK; only libbox and Telegram WS are allowed there. The importer selects a process-compatible ABI and displays each package's actual GitHub byte size before consent. Multiple engines are fetched/installed sequentially in the same import dialog; profile data is committed only after all required engines are present.

The individual APKs are not yet published on GitHub. Download, unknown-source permission and system-installer acceptance require end-to-end verification before publication. Android requires user confirmation; the importer never grants its own installation privileges. Failed/cancelled installation leaves the catalogue unchanged. Pending links are kept in memory across configuration changes, not written as plaintext Android saved state. Settings show installed APK/native byte size and offer independent removal through the Android uninstaller. Built-in libbox/TG WS are not optional uninstallable packages.

OpenFlux auto-update is an explicit pending requirement: inspect the original upstream core/Android repositories, update signed `.flux` transport packages and the compatible Android engine independently, never install a desktop executable as an Android update, preserve the active connection and a working fallback. Current bridge source remains pinned to v0.4.2 until the newer-source build/runtime gates pass; checking upstream metadata alone is not a completed auto-updater.

Debug exit executables are excluded from all release APKs. GPL/source and license obligations must be fulfilled alongside any public binary release.
