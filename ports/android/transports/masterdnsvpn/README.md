# MasterDnsVPN module — source package, verification pending

Pinned upstream: `masterking32/MasterDnsVPN`, MIT,
`acbf1c61f90786f41b975d2e2f616afbce292b29`. The original DNS framing,
session negotiation and encryption implementation are retained. The MCRF
frontend is separate from the standalone CLI.

Import uses explicit `type: "masterdnsvpn"` JSON. It requires domains,
numeric resolver endpoints, an encryption key and an explicit cipher number.
The original XOR default is never silently selected. Methods 0 and 1 are
unencrypted/weak; method 2 is raw ChaCha20, not AEAD; methods 3–5 use AES-GCM.
Existing profile choices are preserved, not silently upgraded on the wire.

Only an authenticated loopback SOCKS listener is exposed. Local credentials
are generated by MCRF; imported profiles cannot select arbitrary CLI files,
listeners, logging or persistence. Workers default to two, with an explicit
range of 1–8. A server policy cannot raise this chosen ceiling. The 512-client
admission queue waits before Accept and releases a slot on actual stream close,
not merely when an asynchronous SOCKS handshake returns.

Cancellation is bound to the owner context, including session setup. Readiness
is an SDK event after listener startup, not polling an unsynchronised flag.
READY is not a claim that arbitrary Internet destinations are reachable.
Original file logs, DNS cache persistence and MTU-result files are disabled.
Only finite adapter diagnostics are exposed; encryption keys are redacted.

The separate module, app editor/import/loader and isolated source-bound
host/native producers are prepared. Ten new Go checks include an owned local
encrypted DNS/SOCKS exchange and the 512-client queue; four JVM checks cover
profile handling and redaction. These checks have not run. Native artifacts,
APK packaging and phone acceptance await the common P3/P4 verification batch.
