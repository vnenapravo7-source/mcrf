# MCRF · Министерство Цензуры РФ (native Windows client)

Single-file native WinForms application, one design and one released executable: `outputs/native/mcrf.exe`. No browser UI, Node.js, or separate main-core download. The embedded sing-box-lx v1.14.2-lx.11 core supports AWG and is extracted to the current user's LocalAppData. Optional OpenFlux, WDTT and CSQTT engines are downloaded separately from the engine release using the in-app download panel. TUN and the Zapret packet driver require Windows administrator permission. Local HTTP/SOCKS5 on `127.0.0.1:10808` does **not** enable the Windows system proxy or redirect the computer's traffic: configure the address in the intended application.

## Working features

- Import proxy links and base64 subscriptions for VLESS (TLS/Reality/XHTTP), Trojan, Hysteria 1/2, TUIC, Shadowsocks (including base64 SIP002 links), VMess, AnyTLS, NaiveProxy, SSH, HTTP and SOCKS5. The UI can fetch an HTTPS subscription URL manually; refreshing it replaces stale entries from the same URL while retaining unchanged selections. HTTPS fetching uses the embedded curl/LibreSSL and CA bundle rather than Windows Schannel, so it also works on systems where WinForms' default TLS handshake fails.
- Import WireGuard / WARP and AmneziaWG 1.x/2.x/3.x `.conf` files, or `wg://` / `wireguard://` / `awg://` links. AWG-specific parameters are passed to the AWG-enabled core.
- User-defined routing lists for domains, CIDR ranges, application names (`app:chrome.exe`) and paths (`path:C:\\...\\app.exe`). Lists can also be loaded and refreshed manually from HTTPS URLs, including raw GitHub text files. Each list can route to the selected proxy, direct connection, or block. Direct exclusions take precedence over proxy lists; unmatched traffic stays direct. Proxy routes fail closed if no node is selected. Updated lists take effect after reconnecting.
- TCP-connect latency sorting for TCP protocols, ICMP latency when available for UDP protocols, and sing-box `urltest` automatic selection when connected. An ICMP timeout does not mark a UDP-only node as failed.
- Native server list, routing editor, settings, status, tray control, and local client log. The log remains readable while the core runs. The settings page has a rights status and a TUN self-test button that checks adapter creation, a direct HTTP 204 request, and a TUN inbound log entry; it does not check a remote proxy handshake. Embedded core files are verified against their packaged hashes on launch.
- Optional OpenFlux v0.2.0 sidecar: import an `openflux://v1/` link, download the engine from the prompted panel, then use it as a selectable routed exit. It is supervised and stopped with the main connection.
- Bundled Telegram WS sidecar: a new profile routes Telegram through the local WebSocket bridge by default, without an extra download. Its live Telegram connectivity has not been tested here.

## Additional implemented features

- Compact fixed 40px server rows retain the 16px font, one-line protocol labels and full-name tooltips. Protocol help links to the user's 3x-ui Tunnels, OpenFlux, CSQTT and WDTT repositories, clearly distinguishing working engines from import-only formats. Opening that help preserves an unfinished import draft.
- DNS no longer contains the redundant modules button. Custom window regions own the rounded corners; native DWM corner rounding/non-client decoration are disabled for this frameless UI.
- Zapret separates a scoped workflow from manual controls. Before scanning, select one or more strategy families: Flowseal, V and YouTube. Results remain in a themed, owner-painted table; applying a strategy is an explicit user action. Each named profile has its own scope and strategy; enabled profiles compile into one winws process with scoped `--new` profiles. First matching profile wins, in visible profile order. Test-only service domains do not leak into the applied profile scope. Per-application filtering remains unavailable and fails closed.
- Every service gets two independent HTTPS requests. YouTube/Discord first responses precede additional probes; confirmation and additional probes overlap, and endpoint repeats do not wait for unrelated slow endpoints. Strategies never run concurrently. Engine preparation is cached, log writes are batched, verbose packet tracing is off by default, and per-stage/slow-service timings are logged. Original network timeouts are retained. These changes do not guarantee real service availability.

- Separate main-screen WARP, Zapret and Telegram panels. Telegram has its own local SOCKS5 listener on 127.0.0.1:19071, independent of the VPN. WS transport does not carry Telegram UDP calls.
- WARP: one-click creation, endpoint scan and activation, no required imported configuration or confirmation dialog. Cloudflare application terms are linked alongside the action. Registration uses the embedded WarpScout directly (third-party relay disabled), reuses the cached account without rotating keys, and supports cancellation. Auto scans AWG/QUIC then WG, checks tunnel data/loss and optionally excludes DME. The exported candidate must pass three warp=on/plus HTTPS checks through the actual bundled app core before application. HTTPS duration is not presented as network ping. MASQUE is not integrated.
- Lowest-known-ping quick server buttons, full flagless names with separate drawn flags, transport labels and active-connection switching. DNS connect/disconnect keeps its popup open. Journal preview rows grow with window height.
- Routing modes: applications OR addresses, applications only, addresses only, addresses IN applications, and addresses EXCEPT applications. Empty intersection scopes fail closed. Hosts and simple Clash text lists are supported, along with 67 service/CDN/ad-block preset URLs.
- Game presets and polling-based game contact recording: exact process attribution, no guessed reverse-DNS names. Addresses and applications from a recording compile to an AND rule. Requires TUN; short-lived or unattributed connections can be missed.
- Owned engine processes are attached to a Windows kill-on-close job; unrelated existing processes are never terminated.

## Known gaps

- WARP creation and a generated AWG exit passed live tests, but a repeat full UI scan did not finish successfully in the test session. Endpoint availability/search time is not guaranteed; the one-click workflow must not be described as fully verified across networks. No account key rotation occurs on retry. Windows TUN is still not live-verified here.

- Zapret has a native popup, a bundled Flowseal 1.10.3 engine, 21 Flowseal / 10 V / 27 YouTube strategies, scoped host/IP profiles, manual start/stop, cancellation and sequential HTTPS strategy selection (two full passes). Existing route lists can populate its scope. No BAT/service/hosts installer is executed. Exact `DOMAIN` entries use strict host matching; unscoped profiles and `/0` networks are rejected. A baseline that already passes is explicitly not proof of DPI bypass. HTTPS probing covers TCP, not QUIC or voice traffic. TUN must be off during selection. Its driver-backed launch still needs verification on an administrator Windows session: this sandbox rejects the Cygwin executable initialization (`0xc0000142`). **Per-application Zapret filtering is not implemented**; apps / in-apps / except-apps and lists containing process selectors fail closed. Do not describe phase two as complete.
- CSQTT and WDTT use optional custom engine packages. Download/install verifies pinned archive and file hashes; CSQTT includes its WDTT bridge dependency. Installed engines become available without restarting the app. qWDTT remains unavailable. Import alone does not prove that a remote server will connect.
- Live tests confirmed HTTP 204 through the local proxy for all ten VLESS and both Hysteria2 profiles in the tested subscription. The supplied non-WARP Sweden WireGuard profile receives a handshake response but still times out on data, including MTU/DNS/keepalive variants; this is unresolved and is not evidence that the user's service is broken. The generated WARP account and AWG exit passed three real app-core trace checks. TUN still requires verification in an administrator session; the sandbox cannot elevate.
- Stored imported links/configurations contain credentials in the current user's `%LOCALAPPDATA%\splify-win\client.json`; do not share this file.

## Updates and Zapret routing

The title bar's **Обновления** opens the update centre. A background startup check (optional) checks public GitHub releases, the MCRF optional-engine catalog, Flowseal/V/YouTube strategies, and every saved route-list HTTPS source. No component is installed by a check. The startup notification offers **Позже**, **Пропустить**, and **Обновить** (opens the centre). Skip persists a component/content fingerprint; a different version is offered again. Manual checking still shows skipped versions. GitHub failures are reported as unknown, not current.

Only a stable release containing `mcrf.exe` is an application release; the engine-only release is excluded. Application updates are downloaded and SHA-256 checked before a separate install/restart action. The replacement helper waits for this process to exit and uses atomic replacement with a recoverable `.previous-*` EXE; profiles are left in place. Live self-replacement requires a separate test with a newer application release; no live replacement test was run as part of these UI checks.

Telegram WS, WarpScout and Flowseal Windows packages are taken from their fixed upstream repositories and require GitHub's SHA-256 asset digest. Optional WDTT/CSQTT/OpenFlux updates use the MCRF catalog (archive and per-file verification). Upstream sing-box-lx versions are checked, but only a source/release link is offered: an unvalidated upstream binary must not silently remove AmneziaWG support. Components use versioned overrides under `updates/installed`; startup extraction does not overwrite them. A failed download does not activate its staging files. Lists get a local backup and refuse to overwrite edits made after checking. A source-less local list has no remote update source.

Routing lists now choose **Zapret → profile** as their exit. This means direct routing plus DPI processing by that profile, not proxying; turning Zapret off leaves that route direct. The Zapret section manages profiles and strategies; its scope preview is read-only and reflects currently enabled assigned lists. Legacy scopes are migrated once. A profile cannot be deleted while lists refer to it. Strategy changes and list updates do not restart active connections. Application selectors and `/0` scopes fail closed; per-process packet filtering is still not implemented. Real driver-backed startup requires testing on an administrator Windows session outside this sandbox.

Tests: `work/UpdatesCheck.cs` covers notification/skip semantics, GitHub channel filtering, routing migration, isolated profile scopes, backup/conflict handling, content overrides and archive validation. Its `live` mode downloads current verified packages into a fixture only. `MCRF_TEST_NO_STARTUP_UPDATES=1` disables startup network checks in UI regression fixtures, not normal builds.

## Build and bundled components

Zapret bundles [Flowseal 1.10.3](https://github.com/Flowseal/zapret-discord-youtube/releases/tag/1.10.3), archive SHA-256 `244314ae1c24538a0d751601da8e0c925c843371eec4456eb15f14c4fd6b7058`, with its MIT license and the WinDivert license. V / YouTube options are parsed from the [Zapret-Manager strategy sources](https://github.com/StressOzz/Zapret-Manager); Linux paths are remapped to bundled payloads rather than executing their installation scripts. Additional fake payloads come from the original [bol-van/zapret](https://github.com/bol-van/zapret/tree/master/files/fake) tree. The source parser separates adjacent Yv21/Yv22 headings even though their Markdown code fence is missing. The app-scoping limitation is displayed directly in the popup.

WARP embeds [WarpScout v0.16.0](https://github.com/vernette/warpscout/releases/tag/v0.16.0), MIT license included. Its Windows ZIP SHA-256 was verified as 8f5c39686b780923fbe0696f6b4b87682a8d840f3ba07e9b726b3ac2ee771b5c. One-click workflow references were inspected in [Zapret-Manager](https://github.com/StressOzz/Zapret-Manager) and [brb](https://gitlab.com/xyzmean/brb); their OpenWrt installation/network mutation scripts are not run on Windows.

The client is compiled with the .NET Framework C# compiler included with Windows (`native/build.ps1`). Its only released executable is `outputs/native/mcrf.exe`; no `7olet.exe` alias is built or copied. Embedded executable/DLL resources are losslessly Deflate-compressed and restored byte-for-byte. Its core was downloaded from the [sing-box-lx release](https://github.com/Leadaxe/sing-box-lx/releases/tag/v1.14.2-lx.11), and the ZIP SHA-256 was checked against the release's `SHA256SUMS` (`0a63389570c675aa7a8820c0e0a61fa8c7a7f3346dcec9773b67bbcfc551bc85`). The embedded [curl for Windows](https://curl.se/windows/) package is version 8.22.0_2, SHA-256 `7c8c6b953b4eb2953d2bdc08cca1d5f09a964e9f86c361693559400c9a6d6db0`, with bundled license files.

Optional packages and corresponding source archives are published separately in [the engine-only release](https://github.com/vnenapravo7-source/mcrf/releases/tag/engines-2026-10-02-1). The application and user profiles are not included in that release. Engine downloads run in the background with progress and cancellation; a failed or corrupt download does not replace a working installation. Sources are not embedded in the runtime EXE; license notices remain available.

The current clean-download build uses a new `optional-engines-v2` storage namespace. Older `core` engines and the v1 download cache are preserved but not used, allowing the first-download scenario to be tested without deleting profiles or engine files. Downloads into v2 persist across app restarts; this is not a reset on every launch.

Third-party components: optional [OpenFlux v0.2.0](https://github.com/p1neappleXpress/OpenFlux/tree/v0.2.0) (GPL-3.0; release SHA-256 `7aeb9ecd54dc26c7e2251fe649ac7a8bf127e119b4d6612c517be7e005e17a64`) and bundled [Telegram Proxy v2.0.7](https://github.com/y0sy4/telegram-proxy/tree/v2.0.7) (MIT; downloaded lite EXE SHA-256 `fcf63a344c754cb9b9b0aba092802ca07b568f8db1ad640daf5bd00f1ac9c3b7`). Their license texts are embedded and extracted next to the cores.

The configuration checker is `work/check-configs.ps1`; local runtime smoke tests are `work/test-routing.ps1`, `work/test-openflux.ps1`, `work/test-tgws.ps1` and `work/test-auto-config.ps1`. The routing smoke test confirmed a direct HTTP 204 response while a domain in the block list failed. Real TUN remains unverified. Current regression tests include `work/current-request-check.ps1`, `work/warp-workflow-check.ps1`, `work/warp-one-click-check.ps1`, and `work/blue-glass-performance-check.ps1`. Animation timing measures submitted positions/UI stalls, not display FPS.
