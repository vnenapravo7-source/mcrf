# MCRF · единый WPF-интерфейс · 13.10.2026

Предрелиз 1.0.11: единый WPF-интерфейс, новый логотип, редактор стратегий и автодеплой с выдачей подключений. TCP/gRPC REALITY и зашифрованный OpenFlux Direct проверены реальным трафиком. Вход через главную vk.ru и получение токена подтверждены пользователем; создание шести реальных звонков, удалённый трафик SWG и другие носители OpenFlux пока не подтверждены. Портирование выполняется после Windows. Старые требования о двух интерфейсах, самостоятельных разделах hosts/подключения и отдельном конструкторе не применяются.

## Запуск

Файл предрелиза: `outputs/native/release-1.0.11/mcrf.exe`. На GitHub публикуется один `mcrf.exe`; дополнительные движки устанавливаются по необходимости.

Один `mcrf.exe`, без отдельного backend-EXE и Theme.xaml. Windows x64, .NET Framework 4.8. Основной EXE запрашивает права администратора. Профиль находится в %LOCALAPPDATA%\mcrf-wpf; основной профиль не импортируется автоматически. Закройте другой MCRF перед запуском.

Опубликован каталог дополнительных движков `engines-2026-10-13-1`: OpenFlux, CSQTT, WDTT и QWDTT. Пользователю нужен только EXE. Движки скачиваются по кнопке с нашего GitHub и распаковываются в папку данных программы после проверки SHA-256; выбор локального ZIP и поиск ZIP возле EXE не используются.

## Интерфейс

- Главная: подключение, серверы, журнал; нижний ряд — маршрутизация, Zapret & Byetube, мастер настройки, обновления.
- Блок подключения сохранён. Отдельной страницы «Подключение» нет.
- Левая панель видна только внутри разделов, полностью прозрачна: собственного цветного слоя нет, подсвечивается только выбранный пункт.
- WARP встроен во вкладку серверов; hosts не самостоятельный раздел. Instagram/ChatGPT находятся над таблицей маршрутизации, остальные hosts-сервисы — в третьем выпадающем списке. Все три поддерживают мультивыбор.
- Основные блоки открываются страницами. Подтверждения, горячие клавиши и редактор правила остаются малыми окнами.
- Общий векторный узор уменьшен и продолжается за карточками/панелью; карточки полупрозрачны над фоном приложения. Это не Acrylic рабочего стола.
- График удалён. Время сессии и наблюдаемая скорость VPN стоят рядом, ниже — автозапуск, «Сброс», горячие клавиши.
- Telegram: включение и подключение рядом; копирование ссылки с главной убрано.
- Кнопки режимов рисуются одной поверхностью с контуром. Логотип не рисует постороннюю рамку при наведении.
- Вся карточка журнала и пустая область карточки серверов открывают соответствующий раздел. Три быстрых сервера — карточки, не выпадающее меню.
- История поддерживает боковые кнопки мыши. Назад/Escape закрывают малое окно, щелчок по основной программе вне окна тоже закрывает его. Escape при вводе горячей клавиши отменяет ввод, а не закрывает окно.

Журнал на главной показывает последние события клиента цветными строками с маркерами, без сетевого потока и технических временных колонок. Полный журнал имеет вкладки, включая «Все события», и единственную кнопку «Копировать» для текущего фильтра. Известные технические сообщения переведены; неизвестные диагностические детали сохранены. Секреты скрываются при копировании.

## Серверы и WARP

Над таблицей VPN — поле импорта и кнопки добавления/файла. Подписки сгруппированы по источникам без раскрытия полного URL.

Автовыбор: выключен / первый рабочий / самый быстрый. Справа сначала период, затем отклонение: последнее видно только в режиме «самый быстрый». При выключенном автовыборе период скрыт. Значения по умолчанию — 60 с и 50 мс; старое значение по умолчанию 300 с мигрирует один раз, остальные пользовательские значения сохраняются. Настройки сохраняются при выборе/завершении ввода.

Первый рабочий проверяется HTTP-запросом через выход, а не одним пингом. Самый быстрый использует urltest и заданные интервал/отклонение.

WARP: переподбор/удаление над нижними полями, кнопка добавления справа от них. Никакие произвольные сайты автоматически не назначаются WARP.

Отсутствующий OpenFlux/CSQTT/WDTT/QWDTT не уничтожает импортированный профиль: он сохраняется и открываются дополнительные движки в обновлениях. Для OpenFlux до установки доступна только проверка формата ссылки; полная проверка выполняется самим движком после установки. Для QWDTT добавлены отдельно скачиваемый Windows-движок, импорт qwdtt://config и выход через SOCKS5. Бинарник QWDTT не включён в EXE. Это предварительная поддержка, а не подтверждение реального подключения к VK/серверу. Импорт JSON-профилей Android отсутствует. Вход VK/ручная капча реализованы в отдельном браузерном окне, но полноценный сценарий SWG ещё не завершён.

## Маршрутизация

Шапка уплотнена, кнопки захвата/шаблонов рядом с заголовком. Строки имеют карандаш и крестик; приоритет меняется перетаскиванием. Отдельные кнопки удаления/изменения/стрелок/обновления/пресетов убраны.

Снизу один ряд: добавить, объединить, глобальное исключение приложений. Пресеты доступны в редакторе. «Популярные сервисы 7» выделены золотым, остальные названия без произвольного разделения цветов.

TCP/UDP помещаются в строках; выходу и DNS выделена минимальная ширина, стрелка DNS соответствует прочим спискам.

Объединение не требует одинаковых исходных выходов или условий: предлагается выбрать выход. Записи/источники объединяются без повторов. Итог включён, условие «приложения ИЛИ адреса», общий DNS; старые индивидуальные исключения не переносятся, это объясняется перед подтверждением.

AppStore можно отключить/удалить даже при ошибке другого старого маршрута. Защита от /0 для Zapret сохранена.

URL в редакторе добавляет записи и источник, не заменяет существующие. После нормализации IP удаление пресета корректно удаляет его записи /32.

Глобальные исключения имеют список текущих процессов, поиск и произвольный ввод **имён EXE**, не полных путей. Дизайн списка общий с захватом процесса.

Основные hosts-поля сверяются с настоящим системным файлом. Если записи изменены снаружи, показывается ручной/другой источник. Системные hosts-операции требуют подтверждения, создают резервную копию и сохраняют чужие блоки.

## Zapret, ByeTube, мастер и редактор

Раздел переименован в Zapret & Byetube. Из ByeTube удалены неподходящие генератор/редактор, из Zapret — дублирующий блок проверки. Проверка находится в мастере, результаты доступны отдельной кнопкой, включая сохранённый отчёт.

Редактор имеет одну горизонтально прокручиваемую ленту блоков: в заголовках только крестик удаления (хотя бы один блок остаётся); «i» у каждого аргумента слева открывает пояснение. Слева аргументы с включением, справа таблица «Название / Значение / Пояснение», предпросмотр внизу. Выбор выключенного аргумента показывает пояснение без автоматического включения. Правая таблица без отдельного фона. Поля однострочные, значки отделены промежутком; длинный BIN показывается сокращённым именем, полный путь — в подсказке и при редактировании. Левая панель адаптируется по ширине, предпросмотр ниже 760 px высоты окна сокращается до 64 px. Режим редактирования — список возле имени копии; сервисы выбираются при «Проверить копию», кнопки отмены нет.

Редактор сохраняет независимую копию, не изменяет исходную стратегию и не выполняет BAT. Генератор ограничен бюджетом, требует повторного подтверждения победителя, поддерживает отмену.

Отчёты копируются перед обновлением UI из фоновой проверки; незавершённые результаты сохраняются при отмене. Автосоздаваемый профиль включён.

## Обновления

Выпадающий фильтр по умолчанию: «Программа и основные движки». Программа первая; дополнительные движки, конфиги и списки — отдельные категории.

Таблица имеет настоящие колонки. Каталоги не дублируются строками рядом с отдельными CSQTT/OpenFlux/WDTT. Flowseal/V/YouTube присутствуют как источники конфигураций.

Основные бинарные пакеты проверяются по собственному репозиторию MCRF, с SHA-256 и совместимостью. Upstream sing-box не устанавливается вместо нужной AmneziaWG-сборки. Если отдельно опубликованного пакета нет, показывается «В составе MCRF», без ложного предложения обновить.

Версия конфигурации — версия релиза, когда установлена точная принадлежность; для снимка ветки не выдумывается номер релиза. Хеши используются внутри, не как пользовательская версия. Нативный mcrf.exe не предлагается вместо WPF-сборки.

Обновление пресета сравнивает и заменяет **его собственную часть маршрута**, сохраняя ручные записи (включая добавленные после проверки), части других пресетов и выбранный выход. Кэш пресета обновляется вместе с маршрутом. Ошибка источника отображается в соответствующих строках, а следующая проверка остаётся доступной.

Публичные источники проверены чтением без установки/публикации. Отдельного совместимого каталога основных движков в проверенном списке релизов MCRF не было.

## Не подтверждено

Режим WpfCoexistence20261013 --tun-zapret запущен с отдельно подтверждённым повышением прав: 36 проверок прошли. Настоящие TUN и ограниченный WinDivert работали одновременно с ByeTube, двумя TG WS процессами и тестовым WARP-узлом. После теста собственный адаптер исчез, собственная служба WinDivert удалена; существующие адаптеры сохранены. Это не проверка удалённой сети Cloudflare или фильтрации провайдера.

Для неё подготовлен WpfCoexistence20261013 с явным режимом --tun-zapret: запускать вручную от администратора с НОВЫМ изолированным каталогом. Он временно создаёт TUN и запускает Zapret только для тестовых доменов/документационных IP, затем останавливает свои процессы. Ни реального VPN-профиля, ни записи hosts он не использует. Не запускать этот режим на рабочем соединении без готовности временно изменить маршруты.

Разные области ByeTube, WARP, TG WS и Zapret не объединяются автоматически. Пересечение областей, исключения по приложениям, чужие VPN и реальная фильтрация сети требуют отдельной проверки. Нет безусловной блокировки ByeTube + Zapret.

Также остаются реальные регистрация/подбор WARP, применение/откат hosts, установка совместимого опубликованного пакета, голос Discord/игровые сценарии, физические боковые кнопки/клики и разные DPI мониторов.

## Автодеплой: текущий объём

Раздел после «Обновления». Компактные строки с промежутками: панель/сервер/SSH-порт/логин; авторизация; настройки панели. Debian/Ubuntu, пароль или SSH-ключ с выбором файла, порт 22 и root по умолчанию.

Перед установкой — подтверждение изменений на сервере и доверия отпечатку SSH. Изменившийся SSH-ключ останавливает установку; существующая панель и занятый порт не перезаписываются. Установщик загружается с закреплённой ревизии и проверяется SHA-256; исходники панели и сервера OpenFlux также закрепляются. Зависимости ОС и дальнейшее обновление панели остаются ответственностью стороннего установщика.

SSH-пароли/ключи не сохраняются в профиле. Пароль панели генерируется. Временный сценарий на сервере закрыт правами и удаляется по точным именам; отмена завершает собственную группу процессов. Завершение установки не откатывает уже выполненные изменения пакетов/сервисов.

После установки требуются активный сервис и ответ локальной HTTPS-панели. Самоподписанный сертификат проверяется по отпечатку, полученному через доверенное SSH-соединение, а не признаётся публично доверенным сертификатом. Проверка снаружи сервера, firewall и фактический вход в панель ещё нуждаются в живом тесте.

«Добавить подключения» импортирует выданные ссылки в «Серверы», не запускает VPN. Кнопка скрыта, пока подтверждённых ссылок нет. Автодеплой создаёт выбранные первоначальные профили: 3x-ui TCP/gRPC REALITY, OpenFlux с выбором носителя, SWG CSQTT/WDTT/QWDTT. Готовые подключения показаны отдельным разделом; попап содержит ссылку, действительный ключ/UUID, локально созданный QR и привязанные звонки. Последний результат сохраняется с DPAPI для текущего пользователя Windows; SSH-пароль/ключ и VK-токен туда не попадают. Сбой локального сохранения не скрывает уже выданные реквизиты: показывается просьба скопировать их.

SWG: кнопка «Создать 6 звонков VK» открывает главную vk.ru, затем «Я вошёл — получить токен» в той же сессии. Работу входа и получения токена подтвердил пользователь. Создание шести звонков выполняется последовательно, без повторения неоднозначно завершившегося запроса; уже полученные ссылки сохраняются в полях. При ручном вводе звонков авторизация не нужна; несколько вставленных ссылок раскладываются по отдельным полям, плюс добавляет пустое поле. Шесть ссылок привязываются к одному пользователю/подключению SWG.

Живой тест 3x-ui на разрешённом VPS прошёл: оба созданных профиля открыли HTTPS example.com через опубликованный в EXE sing-box, без тестового перезапуска после создания. Ошибка совместимости нового REALITY с устаревшим отпечатком Edge устранена выбором Chrome для новых TCP-профилей; Safari для gRPC подтверждён. Старые импортированные профили не изменяются. Тестовая панель удалена; существующий журнал x-ui и прочие службы сохранены.

OpenFlux: закреплённый установщик теперь размещает собственный Go и кэш в каталоге OpenFlux, не удаляет /usr/local/go и не меняет системный симлинк. Живой тест OpenFlux Direct прошёл: профиль создан через API, выдан настоящий 64-символьный ключ, импортируемая ссылка и QR; опубликованный дополнительный Windows-движок передал HTTPS example.com через новый сервер. После теста панель, её сервисы, отдельный Go и кэши удалены; пакеты ОС, системный Go и существующие службы не изменились. QR независимо декодирован в точную серверную ссылку. SWG-трафик и внешние носители OpenFlux ещё требуют живой проверки; успешные моки не считаются подтверждением удалённого трафика.

Исходники QWDTT и Windows-патч опубликованы в QWDTT-source.zip в релизе дополнительных движков на GitHub; пользователю этот архив не требуется. Сборка движка: native/build-qwdtt.ps1; репозиторий и ревизия закреплены. Проверены разбор ссылки, скачивание с опубликованного GitHub-релиза, SHA-256, распаковка, запуск настоящего движка без сетевой сессии и конфигурации sing-box для прокси/TUN. Реальное получение TURN и передача через удалённый QWDTT-сервер не проверены.

## Оценка Linux, Android и iOS

Это инженерный план, а не готовые версии приложения. Цвета, логотип, карточки, порядок страниц и формат профилей можно сохранить; ограничения ОС требуют разных сетевых адаптеров и мобильной компоновки.

### Linux

Клиент визуально близкий к Windows реалистичен. WPF работает только на Windows, поэтому рекомендую Avalonia + современный .NET для общего настольного UI, а не запуск WPF через Wine. Общую модель/маршруты/пресеты отделить от Windows API. [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/), [платформы Avalonia](https://docs.avaloniaui.net/docs/supported-platforms).

Первая очередь — Debian/Ubuntu .deb и Fedora .rpm, x64 и arm64; затем Mint, openSUSE, Arch и CachyOS. Главный UI без root, отдельный привилегированный помощник с Polkit для TUN, DNS и правил сети. Вместо реестра/DPAPI/Windows jobs нужны XDG, Secret Service, systemd и контроль дочерних процессов. Обязательно тестировать Wayland/X11, восстановление DNS/маршрутов после падения и взаимодействие с NetworkManager.

VPN/WARP, подписки, маршрутизация, журнал, редактор, генератор и SSH-деплой можно переносить поэтапно. Движки собираются заново под ОС/архитектуру. Zapret на Linux использует nfqws/NFQUEUE вместо WinDivert; наши Windows-правила по EXE/PID не эквивалентны и требуют нового слоя cgroup/маркировки. [Исходный Zapret](https://github.com/bol-van/zapret).

### Android

Рекомендую Kotlin/Compose для UI и Go/NDK-библиотеки для транспорта. VPN, WARP, domain/IP/DNS-правила и дополнительные выходы должны работать внутри одного VpnService: второй VPN-сервис выключает первый, собственные транспортные сокеты защищаются от попадания обратно в туннель. Системный API поддерживает выбор приложений по пакетам. [Android VPN](https://developer.android.com/develop/connectivity/vpn).

Переносимы импорт/подписки, пинг/автовыбор, маршруты, журнал, пресеты, мастер и адаптированный редактор; SSH-деплой возможен с учётом жизненного цикла. VK/QWDTT можно использовать как основу после проверки лицензий и адаптации авторизации, не копируя чужой UI. По запросу пользователя Zapret и ByeTube в мобильные версии не переносим; VPN всех текущих протоколов, WARP, локальный прокси и маршрутизация остаются обязательными. Системный hosts и произвольный захват процессов заменяются DNS-правилами собственного VPN и выбором пакетов. Вместо глобальных хоткеев/трея — уведомление и плитка быстрых настроек. Проверки: батарея, сон, смена Wi-Fi/LTE, IPv6, DNS/UDP и восстановление после убийства процесса.

### iOS

Нужны SwiftUI, PacketTunnelProvider и сетевой код как библиотека внутри расширения, а не набор запускаемых EXE. Доменная/IP/DNS-маршрутизация, импорт, WARP и совместимые VPN-транспорты — кандидаты для переноса. Сначала доказать минимальный туннель на устройстве, затем адаптировать TURN/QWDTT; указанный VK TURN-проект — полезный референс, не подтверждение совместимости всех наших протоколов. [PacketTunnelProvider](https://developer.apple.com/documentation/networkextension/nepackettunnelprovider), [VK TURN iOS](https://github.com/anton48/vk-turn-proxy-ios).

Нет прямого переноса WinDivert/nfqws, системного hosts или выбора произвольных EXE. Zapret и ByeTube исключены из мобильного объёма по запросу пользователя. Подписки, правила, журнал, диагностика и панельный SSH-деплой можно адаптировать, но долгие фоновые SSH-установки требуют отслеживания серверной задачи после возвращения в приложение.

Публикации в магазинах не будет: нужны APK и IPA для ручной установки (не IPK). У пользователя есть только Mac; доступа к подключённому Mac/Xcode и подтверждённой подписи Network Extension пока нет. IPA с рабочим VPN нельзя обещать до проверки подписи и запуска на устройстве.

### Последовательность

1. Выделить общий контракт профиля, маршрутов, списка возможностей и состояния/журнала; закрыть живые проверки Windows.
2. Linux: общий desktop UI и безопасный системный помощник, затем пакеты и дополнительные движки.
3. Android: один VPN-сервис, базовые выходы и приложение/доменные правила, затем TURN и обходные стратегии.
4. iOS: минимальный Packet Tunnel + импорт/маршрутизация; расширять только функции, подтверждённые на устройстве.

Общий профиль должен явно помечать неподдерживаемые функции, а не молча преобразовывать Zapret в VPN. Секреты — в платформенных хранилищах; обновления подписаны/проверены, конфигурации и бинарные обновления разделены.
