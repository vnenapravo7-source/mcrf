# CSQTT 2.5 · Windows

The Windows adapter builds upstream `amurcanov/csqtt` commit
`d02da9bd9d8926969b766e197c434d830a83dbd8`, the pin used by the
SanityProtocol/swg-panel 2.5 server line. The network protocol is unchanged.
`windows.patch` replaces the public CLI bootstrap with bounded private UTF-8
stdin. No passwords or VK links enter process argv. Structured upstream events
are consumed by MCRF; raw provider logs are not displayed or persisted.

The client runs a loopback raw-IP transport, connected to the separate optional
`csqtt-netstack.exe` IP/SOCKS adapter. The WDTT package is not required.
It does not install a driver, change system DNS/routes,
or create an additional Windows VPN adapter. MCRF owns routing and optional TUN.
Normal upstream STOP/parent-EOF cancellation is retained.

Sealed `csqtt://` links use the authenticated AES-256-GCM envelope generated by
swg-panel `turn-artifacts.js`. The fixed public key is not password-protected
storage. Plain `csqtt://connect?v=2...` links remain the 2.1 protocol; failed
connections never trigger a cross-generation fallback. Generations and the
local IP adapter have separate downloadable packages; none is embedded in MCRF.

Build with `build.ps1` after fetching the pinned pristine upstream into
`<WorkRoot>/upstream` (sparse paths `rust-client`, `shared`, plus root files).
The script uses a fresh build directory and the locked Rust dependencies.
Windows tool paths can be overridden explicitly. `package.ps1` assembles the
new optional archive alongside the unchanged legacy executables.
